# 安全边界

这里说明这个项目读什么、写什么、要什么权限、有什么风险。漏洞报告方式见根目录的 [SECURITY.md](../SECURITY.md)。

**只对你自己拥有或得到明确授权的账号使用。** 有机器的权限不等于有权读别人的聊天。

## 一句话版

这个目录里有能解密你全部聊天记录的密钥，也有解密后的聊天内容。**把 `instances/` 当成密码库对待**：不进 git，不进普通备份，不放到别人能读的机器上。

## 各环节读写什么

| 环节 | 读 | 写 | 权限 | 网络 |
|---|---|---|---|---|
| 桌面容器 | 只读的客户端文件 | `gui/` | 普通用户，无 capability，只读根文件系统，no-new-privileges，内存和进程数有上限 | 微信自己联网；noVNC 只绑 127.0.0.1 |
| `keys check` | 客户端进程的 maps 和少量内存 | 无 | 容器内 root，`SYS_PTRACE`、`DAC_READ_SEARCH`、`DAC_OVERRIDE`、`CHOWN`，共享桌面的 PID 命名空间 | 无 |
| `keys capture` | **客户端进程内存**、每个库的第一页 | `keys/`（600） | 同上；gdb 方式会附加调试器 | 无 |
| `keys image-key` | **客户端进程内存**、几个图片缓存文件 | `keys/image_key.json`（600） | 同上，不附加调试器，不暂停进程 | 无 |
| `export` | `gui/` 下的数据库和缓存（只读复制）、`keys/` | `export/`（700）、`state/` | 你运行它的用户 | 无 |
| `wechat-send` | 要发的内容、`gui/`（只读）、`keys/` | `state/send/`；操作微信窗口 | 工具容器：无 capability，只读根文件系统，普通用户 | 共享桌面的网络命名空间（为了连 X11），自己不发请求 |
| `watchdog` | X11 窗口列表（标题和尺寸） | `state/watchdog/` | 工具容器，无 capability | 配了 `bark_url` 时向它发提醒 |
| 头像下载（`export.avatar_download`，默认开） | 导出排好的头像链接 | `export/media/` | 你运行它的用户 | **访问微信头像域名**（`wx.qlogo.cn` 等四个，不跟随跳转）。容器模式下单独起容器，只挂导出目录，拿不到密钥和数据库 |
| `fetch-originals`（默认关） | 消息里的图片描述、客户端缓存的 CDN 凭据 | `export/media/` | 你运行它的用户 | **访问腾讯 CDN** |
| `serve-media`（默认关） | `export/media/` | 无 | 你运行它的用户 | 只监听 127.0.0.1，要 token |

## 不做的事

- 不修改、不 checkpoint、不删除客户端的原始数据库。
- 捕获阶段不读消息正文，标准输出只有计数，不打印密钥。
- `wechat-send` 不把异常文本写进结果（可能带聊天内容），只写类型和阶段。窗口标题不进日志，只报数量。
- 导出时丢弃 XML 里的下载凭据和文件指纹（`aeskey`、`fullmd5`、`token` 等），也丢弃带这些参数的链接。
- 默认用哈希 ID，导出里不出现微信账号。`id_mode: raw` 会打开它们，只在你确实需要时用。
- 不把数据发给任何第三方。可选的 `bark_url` 只收到「实例名 + 掉线或恢复」。

## 风险，请你知情

- **Docker 权限约等于 root。** 能用 docker 的用户能读所有实例。不要把共享机器上的 docker 权限给不信任的人。
- **密钥捕获是高权限动作。** 容器退出不保证 swap、core dump、备份里没有残留。
- **解密副本落盘。** 导出时明文数据库短暂写在 `state/` 下，结束就删；SSD 上删除不等于不可恢复。需要的话用全盘加密。
- **noVNC 没有密码。** 它只绑 127.0.0.1，靠 SSH 隧道访问。不要把 `VNC_BIND` 改成公网地址。确实要开放到内网时用 `compose.proxy.yaml`（强制 HTTP Basic，而且应该再套一层 VPN）。谁能打开 noVNC，谁就能操作这个微信。
- **`gui/` 含真实聊天和登录态。** 拿到这个目录就可能接管登录。
- **证据截图。** `state/send/evidence/` 存发送前后的截图，标题以下涂黑，标题区域仍能看到会话名；只留最近 40 张。可以用 `send.evidence: false` 关掉。
- **导出是明文。** 消费方（比如总结工具）拿到的就是聊天内容。给它只读权限，别暴露到网络。
- **账号风险。** 自动化操作客户端可能违反微信的服务条款，账号可能被限制。
- **内容不可信。** 消息、XML、文件名都是别人写的。解析时不执行、不访问链接，但你的消费方（尤其是把内容喂给大模型时）要自己防提示注入。

## 建议

```sh
chmod 700 instances
# 备份时排除：
#   instances/*/keys  instances/*/gui  instances/*/export  instances/*/state
```

换账号、重建客户端数据之后，旧密钥作废，要重新捕获，并删掉不再需要的旧 `keys/`。`doctor` 会检查目录权限和密钥能否通过校验。
